# 06 — Backend architecture
Trace: NFR01/02/08–13. Laravel application organized by domain responsibility; avoid speculative enterprise layers.

Request pipeline: trusted proxy → request/correlation ID → rate/session/CSRF middleware as applicable → Form Request shape validation → policy/object authorization → application action → domain rules and transaction → API Resource → normalized response. Controllers are thin transport adapters. Form Requests reject unknown or privileged inputs where appropriate; explicit DTO/field allowlists prevent mass assignment. Resources expose selected fields, never raw models.

Actions represent use cases: PlaceOrder, ReserveInventory, InitializePaymentAttempt, ApplyVerifiedPayment, TransitionOrder, RequestReturn, ApproveRefund and AdjustStock. Money/tax/eligibility calculations can be pure domain services. Eloquent and query builder provide persistence; add a repository only for a demonstrable reusable query/port. Provider gateways are interfaces because external semantics differ, not because every class needs an interface.

Database transactions encompass order snapshots/reservations/outbox, payment application, adjustments and refund-budget reservation. Use deterministic lock order: order (when present), payment/refund parent, inventory rows sorted by variant ID, then reservation children. Catalog edits lock variant rows before stock-related publication validation; checkout takes relevant variant/config locks before order creation and inventory locks. No other workflow may acquire a variant lock after an inventory lock. Keep transactions short; retry deadlocks/serialization errors a bounded number with jitter and idempotency. [09](09-inventory-architecture.md) defines exact stock effects. No provider/email/object-store network call inside a database transaction.

Domain events are persisted to outbox in the same transaction. Jobs claim work with leases, bounded retry/backoff, timeouts and failure records. Workers acknowledge after effects and processed state commit. Notifications consume event IDs with unique delivery keys. Scheduled tasks expire reservations, reconcile pending payment/refund work, dispatch outbox, prune expired secrets/carts and inspect media orphans. Job retry is not permission to repeat a financial POST whose outcome is unknown.

Domain errors map to stable machine codes: OUT_OF_STOCK, QUOTE_CHANGED, PAYMENT_PENDING, ORDER_STATE_CONFLICT, RETURN_POLICY_UNCONFIGURED, RATE_UNAVAILABLE. Unexpected exceptions return safe 500 plus request ID; sanitized internal context is logged. Dependency timeout can return 202 pending if durable work exists or 503 if it does not. Never report a failed order after it committed without returning/recovering its stable reference.

REST/JSON under /api/v1; versioned external contract is distinct from internal action signatures. Validation includes bounds/lengths, NGN only, Nigerian address coverage, integer quantities, safe URLs, allowed sort/filter columns and request sizes. Backend alone calculates totals and eligibility. Policies combine permission and object/state conditions on every action, including jobs initiated by staff; actor/approval evidence is recorded before dispatch.

Logs carry request ID, event/job ID and opaque commerce IDs. They exclude full request bodies, cookies, passwords, tokens, card details, secret keys and unnecessary address/email data. Audit is a separate durable business trail. Framework debug is false outside local/test.
