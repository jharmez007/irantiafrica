# ADR-015 — Durable orders from reserved checkout

2026-09-23. **Implemented under the authorized Phase 3G scope.** Phase 3F is formally approved; Phase 3G acceptance remains separate. Phase 3H is not authorized.

## Authority and decisions

The latest client instruction stages durable orders after approved checkout/reservations, preserves ADR-013 inventory references and forbids provider/payment/shipment/refund/return work. The client delegated selection of the unpaid cancellation policy; selected policy permits the owning customer/scoped guest or Super Admin to cancel PENDING_PAYMENT only before any payment attempt/receipt. Order Processing and Inventory staff cannot cancel. The client explicitly approved a 24-hour absolute order capability and deferred email-link recovery.

1. Copy complete checkout commercial snapshots into orders/items/address. One order per checkout and one inventory reference/current generation per order, all enforced with real FKs and uniqueness. Keep the reference and original expiry; no second hold and no stock consumption.
2. Mark checkout `promoted_at` in the same transaction. Preserve its approved state vocabulary and historical RESERVED snapshot; it is no longer an active checkout or reservation orchestrator. Reads return its order ID; subsequent mutations fail; checkout cleanup skips it. Existing inventory expiry still closes overdue holds. Orders remain PENDING_PAYMENT when a reservation expires, with an explicit ineligible reservation projection.
3. Retain the active source cart and its items. Original architecture 10's placement-time CONVERTED mutation and architecture 08's unique cart/order association are superseded for this stage by the latest non-destructive instruction. Uniqueness is on checkout, not mutable cart. New order attempts require explicit new checkout/reservation; payment retry must use the same order. Phase 3H must not clear unrelated or subsequently edited cart contents.
4. Store immutable complete tax/delivery calculation JSON copied from the approved version bundle instead of a FK to a nonexistent individual shipping-rate table. Retain the actual configuration FK for traceability, never for historical recalculation. Snapshot JSON is bounded by the checkout schema/validators; ownership/money/items remain relational.
5. Implement only PENDING_PAYMENT and CANCELLED. Separate neutral `payment_state=NOT_STARTED`; no provider attempts/receipts exist. Phase 3H must extend the state constraint and make any payment activity block the current cancellation command before a provider request. No fake paid/fulfillment/refund controls.
6. Guest placement derives a separate 256-bit HMAC capability using a domain-separated server secret and placement scope/key. Only authorized placement/replay issues it. Store its digest and fixed absolute expiry; scope its encrypted HttpOnly/SameSite cookie to `/api/v1/orders/{uuid}`. Different guest orders have distinct cookies and grants. Reads do not renew; expiry is checked in PostgreSQL wall-clock time. Guest email matching never transfers ownership. This supersedes architecture 16's emailed-proof exchange for the initial placement grant only; email recovery remains explicitly deferred to a later authorized notification/security task.
7. Append immutable OrderCreated/OrderCancelled event facts to order_status_history and audit metadata in the transaction. This durable event journal is the phase's internal event source; no external dispatch/notifications occur. The earlier generic outbox physical table is not added without a consumer. A later dispatcher needs durable delivery checkpoints/deduplication keyed by event ID; it must never infer a notification was already sent from the journal alone.

## Locking and failure contract

Promotion locks owner → cart → checkout → shared configuration publication guard → inventory reference → reservation → sorted products → sorted variants → balances. InventoryService owns the existing-hold inspection lock protocol. Checkout source revalidation runs while those locks are held. Check exact reservation variant/quantity equality, line sums, tax/delivery/total and final wall-clock deadline. A nested savepoint rolls back partial order/event writes if expiry wins; the outer checkout transaction persists expiry/release rather than rolling those effects away.

Cancellation locks actor → order → existing inventory reference/generation/balances. It never locks checkout or changes snapshots. Same-checkout creation serializes on checkout and returns the existing order, including CANCELLED, without reopening or reacquiring. Shared publication locks allow unrelated checkouts to proceed concurrently. Transactions have bounded three-attempt framework concurrency retry.

Schema triggers reject order deletion/commercial mutation, item/address/history mutation and unsupported lifecycle changes. These are defense in depth, not substitutes for application authorization. Runtime DB permissions remain least-privilege; future reviewed anonymization needs a distinct migration/workflow rather than silently bypassing immutable records.

## Later boundary

Verified payment and exact stock commitment belong to Phase 3H. Check order eligibility, receipt/reference/currency/amount, no cancellation/financial hold, active matching generation and database deadline under locks. A late/extra/mismatched receipt is an exception, not authority to reopen/mark paid/consume. No automatic stock reacquisition, refund or order-number invoice semantics are introduced. Orders retain historical totals for later same-order retry.
