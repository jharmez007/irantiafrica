# Session and inventory audit security — Phase 3N UAT addendum

The broader threat model is [19 — Security threat model](19-security-threat-model.md). This addendum records the client-approved local UAT session change and the inventory history projection; it does not authorize a production policy change.

Staff MFA remains mandatory on a new password-verified session. A successful TOTP or one-use recovery challenge rotates that session and stores only the verified user/version and time as completed-session trust in encrypted PostgreSQL. Normal navigation uses that server-side trust; no TOTP code, authenticator secret, bearer token or remembered-device credential is placed in localStorage or the session. Enrollment temporarily stores an **unconfirmed** setup secret encrypted in the existing Redis cache under a user/session-scoped key for at most ten minutes; only the pending timestamp is in the session, and confirmation deletes the cached secret. Cache loss fails closed and requires enrollment to restart. Local UAT has a 24-hour PostgreSQL idle expiry, 24-hour completed-staff idle and absolute limits, and a 24-hour MFA trust limit. The ten-minute pending-MFA limit and five-minute password-plus-TOTP recent-auth check for owner-sensitive operations remain separate. Logout invalidates the session; expiry, password reset, role/identity revocation and MFA reset remove effective trust. A new login requires MFA again. There is no suspicious-login risk engine; adaptive re-challenge is a future enhancement, not an implemented protection.

Cookie policy remains HttpOnly, SameSite=Lax and host-only, with Secure required for HTTPS; local HTTP explicitly disables Secure. PostgreSQL session expiry rejects stale records independently of scheduled cleanup. Production retains the shorter prior staff defaults unless its own environment configuration and approval change them.

Inventory staff history is an inventory-scoped projection. Manual stock reasons and the actor's display name are operational reconciliation data. Automated reservation, sale, release and return-restock movements use controlled display reasons so internal reference IDs and unrelated notes never enter that projection. A null actor displays **System**, and a missing historical actor displays **Unavailable**. Owner `audit.read` retains complete stored details. Inventory staff receive no actor ID/email, IP, authentication metadata, operation key or reservation/return reference. On-hand and reserved ledger deltas/balances remain distinct; only reservation/order services alter reserved stock.
