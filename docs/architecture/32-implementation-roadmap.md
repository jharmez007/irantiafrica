# 32 — Future implementation roadmap
**Plan only — do not execute during Phase 2.** All phases depend on explicit architecture approval and authorization to implement. Sequence may be refined for staffing, but integrity/security dependencies cannot be bypassed. Nov 1 is a flexible preferred target, not a promised completion date.

Foundation compatibility proof is narrowly scoped future work, not permission now to scaffold the entire app. No legacy migration phase: initial catalog loading is a reviewed import/create process with opening inventory ledger entries. No implementation phases for deferred features or additional business-system integrations.

Estimate after architecture approval using these deliverables, team capacity, policy turnaround, assets and provider onboarding. Record external lead times separately from engineering effort. Each phase ends with reviewable evidence and scope check; failures pause dependent phases, not a silent weakening of controls.
