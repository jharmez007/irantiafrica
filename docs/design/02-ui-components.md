## Shared primitives

Import primitives from `@/components/ui`. The implementation is in `frontend/src/components/ui/index.tsx`, with interactive controls in `interactive.tsx`. Components use semantic CSS classes; palette, spacing, focus and motion rules belong to the shared stylesheet rather than individual pages.

| Component                     | Public props beyond children                                             | Usage and behavior                                                                                                                                                                                                                               |
| ----------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Button`                      | Native button props; `variant?: primary \| secondary \| quiet \| danger` | Real button for actions. Specify `type="button"` for non-submit actions inside forms. Primary is the default. Danger is reserved for destructive actions, independently of the brand accent.                                                     |
| `IconButton`                  | Native button props; required `label`                                    | Supplies an accessible name and defaults to `type="button"`. Decorative icon content is hidden from assistive technology.                                                                                                                        |
| `Link`                        | Next.js Link props                                                       | Navigation rendered as a link with the shared `text-link` class. Do not substitute buttons for navigation.                                                                                                                                       |
| `Input`, `Select`, `Textarea` | Native element props                                                     | Preserve native labels, validation, keyboard interaction, disabled state and form submission.                                                                                                                                                    |
| `PasswordInput`               | Native input props except `type`                                         | Password field with a labelled Show/Hide button and pressed state. Revealing a password changes presentation only; it does not alter submission, validation or storage.                                                                          |
| `Checkbox`, `Radio`           | Native input props except `type`                                         | Native choice controls with shared styling. Consumers supply the associated label.                                                                                                                                                               |
| `FormField`                   | `label`, `htmlFor`, optional `hint`                                      | Groups a label, supplied control and hint. The control must have the matching `id`. A single child control receives the hint ID in `aria-describedby`, preserving existing descriptions; consumers supply error IDs.                             |
| `FieldError`                  | Optional `id`                                                            | Error text with `role="alert"`. Error meaning is communicated in text and a symbol as well as color.                                                                                                                                             |
| `Badge`                       | `tone?: neutral \| success \| unavailable`                               | Compact textual state. Tone defaults to neutral; stock is never indicated by color alone.                                                                                                                                                        |
| `Price`                       | `value: string \| null`, `max?: string \| null`                          | Accepts approved integer minor-unit strings and delegates exact NGN formatting to `money()`. Different minimum/maximum values render a range. A null value renders “Price unavailable.” No floating-point price conversion or invented discount. |
| `Breadcrumbs`                 | `items: { label; href? }[]`                                              | Labelled navigation with an ordered list. A current non-link item receives `aria-current="page"`.                                                                                                                                                |
| `Alert`                       | Optional `title`, `tone?: error \| success \| info`                      | Error tone uses `role="alert"`; other tones use `role="status"`. Text carries the meaning independently of its visual treatment.                                                                                                                 |
| `EmptyState`                  | `title`, optional `description`                                          | A semantic section with a heading and optional action content supplied as children. Do not add fictional products or counts to fill the space.                                                                                                   |
| `Skeleton`                    | Native div props                                                         | Decorative loading shape, hidden from assistive technology. Its surrounding component supplies a readable loading status.                                                                                                                        |
| `Pagination`                  | `page`, `lastPage`, `href(page)`, optional `label`                       | Previous/next links retain real URLs, `rel` attributes and accessible “Previous page”/“Next page” names. Boundaries render text rather than inactive links. Callers preserve their query state in `href`.                                        |
| `Container`                   | Optional `className`                                                     | Shared page-width and side-spacing wrapper. The caller owns the page landmark.                                                                                                                                                                   |
| `SectionHeader`               | `title`, optional `eyebrow`, `description`                               | Section heading and supporting copy; children may supply a related navigation link.                                                                                                                                                              |
| `Modal`, `Drawer`             | `open`, `onClose`, `title`                                               | Native `<dialog>` with a labelled heading, close button, Escape handling and focus restoration. Drawer uses the same interaction model with a different visual placement. Browser focus behavior remains part of final keyboard QA.              |

Server-compatible primitives remain separate from the client-only interactive implementations. A server-rendered pagination callback is therefore evaluated in the server component tree rather than serialized across a client boundary.

## Catalog components

These components live under `frontend/src/components/catalog/` and import the same public types from `@/lib/catalog`.

| Component        | Props                                                                     | Responsibility                                                                                                                                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ProductCard`    | `product: Product`, `priority?: boolean`, `heading?: h2 \| h3`            | One real product link containing its supplied image, categories, name and exact price/range. Defaults to an `h3`; catalog listings request `h2`. Shows a textual out-of-stock badge only when appropriate. No cart action.                                          |
| `CategoryCard`   | `category: Category`, `image?: CatalogImage`, `index?: number`            | Category navigation with an optional real product image. Without an image, an abstract numbered panel supplies visual structure without pretending to be product photography.                                                                                       |
| `ProductImage`   | `image?: CatalogImage`, `priority?: boolean`, `sizes?: string`            | Uses the existing safe derivative URLs, deduplicates actual source widths, retains alt text and dimensions, and sets eager/lazy loading appropriately. A missing image produces a neutral “Image unavailable” surface. No remote image importer or new image proxy. |
| `CatalogList`    | `result`, `categories`, `params`, optional `title`, `path`, `description` | Editorial introduction, native search/category/sort form, real results total, product grid, empty state and pagination. Category-page filter changes submit to `/products`. Existing price constraints survive submission as hidden fields.                         |
| `CatalogLoading` | None                                                                      | Readable loading status and decorative card skeletons.                                                                                                                                                                                                              |
| `CatalogFailure` | Optional safe `message`                                                   | Shared catalog error treatment and a real retry/navigation link. No raw exceptions or debug output.                                                                                                                                                                 |
| `CatalogShell`   | `children`                                                                | One `main#main-content` and a `Container`. Global storefront navigation is not duplicated.                                                                                                                                                                          |
| `ProductDetail`  | `product: Product`                                                        | Product breadcrumb, gallery, name, exact price, generic variant selectors, textual availability, SKU and supplied description. Thumbnail buttons expose pressed state and remain keyboard accessible.                                                               |

`ProductCard` and `CategoryCard` are exported from their own catalog files, not from the shared primitive barrel. This avoids coupling generic form and layout controls to commerce types.

## Behavior that visual work must preserve

- `resolveVariant()` and `optionAvailable()` remain the existing source of variant-selection behavior. Unsupported or unavailable combinations retain disabled option labels. Generic option names are not replaced with hardcoded size/color fields.
- Public stock presentation uses `available` booleans. Exact stock, reservations, thresholds and internal inventory records are never surfaced by these components.
- Stock-hidden listing behavior and informational sold-out details remain backend decisions. Presentation does not republish, synthesize or mutate products.
- Product names, descriptions, image alt text, category names and prices come from the API. No generated product records, ratings, sale prices, delivery promises or certification claims are introduced.
- Auth and admin components retain their existing state transitions, MFA checks, CSRF requests, errors and role boundaries beneath the visual layer.
