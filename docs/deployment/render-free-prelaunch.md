## Free-service design

Use one Free Docker Web Service and this one Free PostgreSQL database. Nginx, PHP-FPM, standalone Next.js, one database queue worker and one `schedule:work` process run in the approved container. Use its private, same-region database URL in Render configuration. Set `QUEUE_CONNECTION=database`, `CACHE_STORE=database`, `RATE_LIMIT_CACHE_STORE=database`, and `SESSION_DRIVER=database`; do not provision Redis. Keep `APP_ENV=production` inside the container for the existing fail-closed guards while labeling the deployment and all data **TEST ONLY**. Set `APP_DEBUG=false`, secure/HttpOnly/encrypted database sessions, `PAYSTACK_MODE=test`, `PAYSTACK_LIVE_APPROVED=false`, `PAYMENTS_ENABLED=false` initially, `TRANSACTIONAL_EMAIL_ENABLED=false` initially, `PRODUCTION_PREVIEW_NOINDEX=true`, and `PRELAUNCH_GATE_ENABLED=false`. Use a unique test-only `APP_KEY` and renderer key in Render private environment settings. Use only TEST Paystack keys and a test inbox. Never copy final production secrets or owner credentials into this temporary environment.

The assigned HTTPS origin is `https://iranti-africa-free-test.onrender.com`. Keep `SITE_URL` (build-time), `APP_URL`, `FRONTEND_URL`, `TRUSTED_ORIGINS`, `SANCTUM_STATEFUL_DOMAINS` (hostname only), and `CATALOG_MEDIA_ORIGIN`. `APP_URL` and `CATALOG_MEDIA_ORIGIN` must be identical HTTPS origins. `API_INTERNAL_URL=http://127.0.0.1:8080` and `NEXT_PUBLIC_API_URL=/api/v1` remain same-container/same-origin. The Free rehearsal uses `FILESYSTEM_DISK=render_free_private`, `CATALOG_DISK=render_free_private` and `CATALOG_UPLOAD_TRANSPORT=proxy`. That dedicated local disk is rooted outside `public/`, has no Laravel serving route or public symlink, and media is read only through `/api/v1/media/{id}/{size}`. It has no durability guarantee. **FREE TEST MEDIA = EPHEMERAL:** uploads and derivatives may disappear on redeploy or restart. Use disposable images only; do not upload final business-only photography or treat this as a durable-media test. Real production still requires private R2/S3 and its scoped credentials.

If catalogue data is needed, explicitly import temporary content and disposable image assets through the approved admin workflow; keep source assets available for re-upload after redeploy. Record exact evidence or **NOT VERIFIED** for each item. R2 upload/derivative/read/delete remains a separate paid-production gate after the owner activates R2.

After validation, take an independent local logical `pg_dump` from the external TLS connection, record its timestamp and checksum, and perform a disposable restore drill if feasible. Render Free database retention is not a backup. Do not use Free web memory, latency or cold starts to approve the paid 2 GB production capacity. [Free web](https://render.com/docs/free) sleeps after inactivity (about 15 minutes), incurs a cold start, has an ephemeral filesystem, no production SLA, and shares 750 free instance-hours per workspace per calendar month. Render may restart Free services. The [Free PostgreSQL database](https://render.com/docs/free) is limited to 1 GB, expires after 30 days, may undergo maintenance or restart, and has no managed backups. Review current provider limits before use.
