# Controlled production pre-launch and launch

**Not authorization to deploy or charge.** Phase 3O remains open; no Render resource has been provisioned. The business owner approved the [ultra-lean topology](../architecture/adr/018-ultra-lean-production-deployment.md): one Render Docker web service plus PostgreSQL 18. No separate staging, Render Key Value, worker or cron. Protected production PRE-LAUNCH uses Paystack TEST. Record operator, owner, time, approved SHA, hosted CI run and observed results in a private launch log.

1. **Before any provisioning:** complete the [environment checklist](production-environment-checklist.md) and [conversion gates](../deployment/render-ultra-lean-proposal.md). Review a clean committed `main` SHA, green hosted CI, actual Docker build, Supervisor kill/restart/SIGTERM, 2 GB/one-CPU traffic and image load, small-Postgres connection/query/table-growth test and overlapping-scheduler handover. Resolve all failures before creating resources.
2. **Provider and owner preparation:** approve Frankfurt/data handling and billing; create private R2 bucket and scoped credentials; verify Resend domain/sender; prepare Paystack TEST only. Arrange PostgreSQL backup/PITR and an independent restore drill. Set production tax, delivery, stock threshold, policy and catalogue content from owner-approved values, not UAT fixtures. Retain secret values only in Render private configuration.
3. **Provision only after separate go-ahead:** create Render PostgreSQL 18 and one `1c-2g` Docker web from approved `render.yaml`, auto-deploy off. Inject the private DB URL, R2/SMTP/Paystack credentials and Laravel key. Keep `PRELAUNCH_GATE_ENABLED=true`, `PAYMENTS_ENABLED=false`, TEST mode and refund/transactional delivery off. Build with correct public `SITE_URL`/CSP origins. Pre-deploy runs `php artisan migrate --force`; inspect status. Never use `migrate:fresh` or UAT seeders.
4. **Private infrastructure checks:** run `php artisan app:readiness`, `php artisan migrate:status`, and `supervisorctl status` in the web container; all five programs should be RUNNING. Test a queued job, failed-job view, worker restart, scheduler freshness, database-cache locks and old/new deployment overlap. Verify `/api/v1/health`, storefront synthetic request, redacted logs, alerts and backup restore. Check actual PostgreSQL TLS/private endpoint, role permissions and resource metrics. A healthy HTTP endpoint alone does not prove worker/scheduler health.
5. **Identity and media:** bootstrap owner interactively with `php artisan identity:bootstrap-owner`; enroll MFA and retain recovery codes privately. Verify CSRF, secure host-only cookies, HTTPS, rate limits and Basic Auth. Test R2 upload with exact size/checksum, one queued derivative, public controlled retrieval, deletion and object recovery. Never make the R2 bucket public.
6. **Email and TEST payments:** test invitation, setup/reset, order and shipping mail to approved inbox with Resend, including bounce/retry. Activate transactional email only after those checks. Configure signed TEST Paystack webhook on the gated Render origin; deliberately enable TEST payments and verify success/failure, duplicate/late webhook, order and inventory state, reconciliation and TEST refund if available. No LIVE key or real charge without separate explicit owner approval.
7. **Protected UAT and cutover:** smoke homepage, catalogue, search, cart, guest/account checkout, admin MFA/catalogue/inventory/orders/reports, mobile accessibility, logs, queues and scheduler. Repair and retest failures. Rehearse [rollback](rollback-runbook.md). After owner/technical sign-off, attach approved domain, update all origins/callbacks/CSP and rebuild from the same approved SHA. Verify HTTPS, session/CSRF and SEO before removing the gate.
8. **Public/live activation:** require separate business approval for LIVE Paystack and any real charge. Switch matching key/mode/callbacks, set live approval and payment enablement only after TEST acceptance. A reviewed Blueprint edit plus manual deploy is required because it pins TEST/disabled/gate-on defaults. Activate refunds separately. Remove Basic Auth only after all launch gates pass; watch orders, stock, holds, queue age, email and database capacity with named responders.

Hard stops: dirty/unreviewed artifact or failed CI; untested Docker/process/resource/PostgreSQL capacity; no backup/restore; R2/SMTP/TEST Paystack failures; missing business policies/content approval; broken HTTPS/cookie/CSRF/MFA or scheduling/queue idempotency. Keep the pre-launch gate and live payments disabled while any stop remains.
