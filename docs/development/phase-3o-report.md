# Phase 3O — Ultra-lean production conversion evidence

Date: 2026-10-04. **OPEN. NOT PROVISIONED. NOT LIVE.** Owner-approved [ADR-018](../architecture/adr/018-ultra-lean-production-deployment.md) replaces the earlier Redis/worker/cron production topology for initial deployment. `render.yaml` is now a two-resource configuration only: one Docker web plus PostgreSQL 18. No Render resource was created. Native local Redis remains unchanged.

## Converted

- Active Laravel-standard `jobs` migration, indexed queue, existing `failed_jobs`; database connection with 90-second lease and after-commit dispatch. No `job_batches` because no batching is used. Worker priority `identity,default,transactional,media`, one process, three-second idle sleep, 60-second timeout, 256 MB process limit and hourly max-time restart.
- Removed explicit Redis connection pins from `RecoveryNotification` and `NotificationDelivery`. Staff invitations use password recovery notification; transactional outbox and media/payment/refund jobs follow configured transport. The signed webhook inbox and domain idempotency/fencing are retained.
- Production Render database profile requires injected private PostgreSQL URL, TLS `require`, database queue/cache/limiter and database sessions; existing debug/HTTPS/cookie/Paystack/private-media guards remain. Local Redis profile is unchanged. `app:readiness` chooses database queue/cache checks without Redis in this profile.
- All scheduled events use shared database `onOneServer()` locks. Long-running business scans keep `withoutOverlapping()`. Hourly cache/cache-lock expiry and session cleanup are scheduled.
- Supervisor now manages Nginx, two-child PHP-FPM, Next standalone, worker and `schedule:work` as `www-data`, with stdout/stderr logs and TERM windows. Dockerfile uses PHP 8.5 and Node 24, removes Composer from final image and sets 12 MiB PHP upload ceiling for bounded R2 proxy uploads.
- Private R2 path uses signed/authenticated upload to Laravel, exact 10 MiB-or-less declared size/SHA-256 check and ACL-free PutObject. Derivatives use the same private write. Existing S3 POST transport remains for other S3 providers/local profiles. Resend SMTP is the preferred provider; no credentials are stored in source.
- Blueprint, [deployment runbook](../deployment/render-production.md), [environment checklist](../production/production-environment-checklist.md), [launch](../production/launch-runbook.md) and [rollback](../production/rollback-runbook.md) describe only the approved ultra-lean production path.

## Local verification

- Isolated PostgreSQL 18 `iranti_test` database on temporary localhost port 55432; no `iranti_local` or UAT catalogue migration/reset. Database-runtime integration tests cover named queue, delayed claim, expired lease, retry, failed-job storage, after-commit/rollback, worker re-invocation, database cache/locks/expiry, rate limiting, encrypted MFA enrollment, queued recovery email, queued image derivatives/idempotency and scheduler mutex: **8 tests passing**. Focused payment webhook follow-up and transactional email duplicate-delivery tests pass on the database queue.
- Release-candidate clean PostgreSQL 18 migration: all 17 migrations applied, including standard `jobs` with two indexes; a repeat pass reported nothing to migrate. Final full backend suite on the isolated test database: **242 tests / 5,758 assertions, one intentional skip** (the opt-in hardening workload requires a different test port/profile). Pint, Larastan, Composer validate and Composer audit pass. Frontend `npm ci`, formatting, ESLint, TypeScript, 262 Vitest tests and standalone-compatible Webpack production build pass.
- `npm audit` reports five high-severity findings through dev-only `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces@3.0.3` ([GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)). The advisory lists **no patched version** as of 2026-10-04; Next plugin 16.3.8 retains `fast-glob@3.3.1`. `npm audit --omit=dev` reports zero production-dependency vulnerabilities. No `--force` or major downgrade was applied. [ADR-019](../architecture/adr/019-dev-tooling-audit-exception.md) and `scripts/check-frontend-audit.mjs` narrowly permit only this complete dev-tooling chain while CI continues to block any production or additional development advisory. The current standalone output excludes the affected packages; final Docker image inspection is pending.
- Two simultaneous `schedule:run` processes used the same isolated PostgreSQL database cache. The due `inventory:expire-reservations`, `checkout:expire`, `payments:reconcile`, `refunds:reconcile` and `notifications:relay` commands ran once each; the second process explicitly skipped `checkout:expire` after its peer claimed the lock. Both exited successfully. This checks shared scheduling mutex behavior, not deployment overlap or missed-cycle recovery.
- [Release working-tree inventory](phase-3o-release-review.md) classifies the modified and untracked candidates. Candidate and five-commit history scans found no confirmed credential or private key; only blank examples, runtime variable references and synthetic test fixtures. No tracked `.env` file was found.
- The first hosted backend run exposed one environment-dependent test assertion: `IdentityStorageTest` aged a session by 10,000 seconds, while CI's copied `.env.example` sets a 1,440-minute session lifetime. The test now ages the row beyond `config('session.lifetime')`; no application session behavior changed. The affected class passed **3 tests / 61 assertions**, and the full local suite under `SESSION_LIFETIME=1440` passed **242 tests / 5,758 assertions / one intentional skip**. Pint and Larastan also passed after the correction.
- The actual `Dockerfile.render` image built in local Podman after two build/boot defects were found and fixed: PHP 8.5 already includes OPcache, and Nginx needed an absolute FastCGI include plus writable uwsgi/scgi temp directories under the non-root user. The final image reports PHP **8.5.11**, Node **24.21.0**, all required extensions, `www-data` UID 33, writable Laravel storage, Next standalone output, no Composer binary and no affected ESLint-chain packages. `nginx -t` passed. The image booted against the isolated native PostgreSQL 18 database with a **2 GB/one-CPU limit**; Nginx, PHP-FPM, Next, queue and scheduler all entered RUNNING. `/api/v1/health` and `/` returned HTTP 200; private `app:readiness` passed PostgreSQL/queue/cache.
- Each of the five Supervisor children was terminated by exact PID and returned to RUNNING with a new PID; HTTP health remained 200. A delayed synthetic media job stayed present, unreserved and at zero attempts after a queue-worker replacement and after full container shutdown, then was deleted from the test database. Container stop completed in **1.68 seconds**, inside the 240-second Render allowance. Logs show Nginx/PHP-FPM exit 0, queue exit 0, scheduler TERM, Next TERM/143 and Supervisor exit; no restart loops after the fixes.
- Under that local limit, combined memory was **154.2 MB idle**, **159.3 MB after representative requests** and **151.2 MB after child restarts**; CPU snapshots were 5.81–8.40%. Warm local request samples: `/` 135 ms, `/products` 50 ms, `/api/v1/products` 18 ms, `/checkout` 11 ms, `/admin` 7 ms. The isolated empty database showed two connections including the measuring client. These are smoke-test observations, not peak load measurements with a populated catalogue, authenticated admin, active checkout, email or image jobs. The 2 GB plan looks plausible for idle/low traffic but is **not yet capacity-approved**.
- The PostgreSQL database-queue test suite covers normal/named/delayed jobs, retries, backoff, `failed_jobs`, after-commit, expired lease, worker handover, array-mail delivery exactly once, three image derivatives with replay-safe audit, and duplicate payment follow-up without a second stock/payment effect. Actual image/email work was not measured concurrently with the combined web container. The native PostgreSQL 18 cluster is not equivalent to Render's smallest 0.1 CPU/256 MB tier; connection, queue-claim/query latency and growth on that constrained tier remain **NOT VERIFIED**. Four named queue probes every three seconds suggest ~80 idle polls/minute, not a measured rate.
- Direct R2/Resend/Paystack provider tests remain **NOT VERIFIED** (no production credentials/resources). Hosted CI, constrained PostgreSQL capacity and populated-data resource testing remain separate release/provisioning gates. No Render resource was created.
