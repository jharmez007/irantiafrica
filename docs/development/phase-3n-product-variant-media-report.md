# Phase 3N product variant and media UX remediation report

Version 1.0 — 2026-09-29. Phase 3N remains **OPEN** for client UAT. Phase 3O has not begun. This follow-up addresses ADMIN-UX-022–024 in the [defect register](../uat/02-defect-register.md). Approved catalog, SKU, stock, cart, checkout and order rules remain in force.

1. **Image upload redesign.** Choosing or dropping a file shows only a compact filename beneath the labelled JPEG/PNG/WebP picker. The large pre-upload preview and object URL code are gone. A successful upload clears the file picker, filename and temporary image description. A failed upload keeps them for retry.

2. **Gallery behavior.** The existing compact card grid remains the preview/management surface. Upload re-fetches the product, so the new card appears in the gallery while processing; automatic polling updates it to Ready. A single card is capped on wider editors and fits the mobile column. Existing reorder, description edit and confirmed removal remain unchanged.

3. **Option value removal.** Each saved value appears as a wrapping chip with an accessible `Remove [option] [value]` button. Removal immediately updates the returned product and combination count. The new versioned, audited endpoint is restricted to Draft products without any saved variants; stale versions conflict.

4. **Whole-option removal.** A confirmed Remove option action deletes its values and the option only while the product is Draft with no variants. After any variant exists, the control is disabled and explains that saved combinations, SKUs and history must remain intact. No backend endpoint can bypass this guard. The owner may remove individual saved combinations from sale instead. The post-generation structural option-removal request remains intentionally unsupported because this schema requires every saved variant to retain one value per option and historical foreign keys restrict deletion.

5. **Individual variant removal.** A compact table action confirms **Remove from sale** or **Restore to sale**. It calls the existing versioned `PATCH /admin/variants/{id}` status transition. There is no variant hard-delete endpoint. The user sees Active or Removed from sale; saved SKU, price, stock and commercial history stay on the record. The backend still blocks an edit that would leave a published product unpublishable.

6. **Historical safety.** PostgreSQL restricts variant deletion from inventory, reservations, cart, checkout and order references. The implementation takes the conservative path for every saved variant, even an unused draft: archive rather than guess whether it is safe to physically delete. The focused integration test verified the variant row, SKU, option value and inventory movement persisted after removal from sale; the catalog/cart/checkout/availability suite verified saleability rules.

7. **Regeneration.** The generator reports total, saved and new combination counts. It excludes all existing signatures, including archived variants, so adding values can create only new combinations. Existing SKU/price records are not overwritten or regenerated. Empty options block generation; over 100 combinations give a clear limit message. Values/options cannot be removed after generation, eliminating destructive regeneration diffs. Bulk removal was omitted because the existing API has no safe bulk command.

8. **Responsive QA.** Browser inspection at 320, 375, 768, 1024 and 1440 px is pending an authenticated local staff session. Chrome showed an expired staff session; the owner was asked to sign in and complete MFA, but that handoff had not completed during this review. The CSS uses wrapping chips and a labelled internally scrolling variant table; the gallery retains responsive card sizing. No viewport is marked PASS without Chrome inspection. Manual follow-up at **each** width: open a draft configurable product's Pricing & Variants tab and its Images tab; confirm chips wrap, removal controls remain reachable, the variant table scrolls internally without page overflow, the selected filename is compact and no large preview appears, and a single gallery card does not stretch across the editor.

9. **Accessibility.** The file picker and description retain labels. Value buttons have specific accessible names; the variant table has a labelled scroll region. Option and variant removal use native confirmation dialogs, which support keyboard focus and cancellation. State is stated in text, never color alone. Browser keyboard follow-up: tab to the value controls and variant actions, verify visible focus; activate/cancel each confirmation with keyboard only; verify status and save errors are announced. This remains **NOT VERIFIED** until staff sign-in.

10. **Frontend validation.** The full Vitest suite passed: **21 files / 220 tests**. Tests cover no large preview, filename/reset and gallery insertion; value/option removal and count changes; explicit saved-variant archiving; preserved SKUs; and duplicate-generation filtering. ESLint, Prettier and standalone TypeScript passed. The webpack production build compiled and generated all 28 static pages. `npm audit` was attempted but **NOT VERIFIED** because `registry.npmjs.org` DNS failed.

11. **Backend validation.** Focused PostgreSQL test passed: **1 test / 34 assertions**. The affected catalog/cart/checkout/availability regression passed: **54 tests / 1,420 assertions**. Pint and Larastan passed. `composer audit --locked` was attempted but **NOT VERIFIED** because `repo.packagist.org` DNS failed. Tests used a temporary isolated PostgreSQL 18 cluster on port 54321, separate from the persistent development database.

12. **Defect status.** ADMIN-UX-022–024 are remediated in code with automated developer retests passing; client retest remains pending. Chrome visual/keyboard sign-off remains pending staff login. The conservative post-generation option lock is an explicit safety limit, not a silent deletion. No production configuration or commerce flow was changed.
