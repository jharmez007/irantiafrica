# Identity and RBAC — Phase 3N inventory staff revision

The maintained RBAC reference is [rbac.md](rbac.md), with the approved current matrix in [architecture 17](../architecture/17-rbac.md). This note records the 2026-10-02 UAT change to the Inventory / Store Staff role.

`inventory_store` has exactly `catalog.read_internal`, `inventory.read`, `inventory.adjust`, `inventory.movements.read`, and `reports.stock`. `inventory.adjust` authorizes existing opening stock and signed, reasoned on-hand adjustments through `InventoryService`; it does not authorize reserved-stock edits or direct balance writes. Each operation uses a version/idempotency key, immutable movement and audit records, and the server's no-overdraw rule.

The owner retains these capabilities plus `inventory.threshold.configure` and `audit.read`. Inventory staff may view the current threshold, movement kinds/deltas/balances, stock reports, the responsible actor's display name and operational inventory reasons. They cannot configure the threshold or read full audit records, actor IDs/emails or internal reservation/return references. Manual opening/adjustment reasons appear as entered; automatic movement reasons use controlled inventory-facing labels. A null actor is shown as **System** and an unavailable historical actor as **Unavailable**. They gain no product pricing/content/publication/deletion, staff, order, payment, refund, return-case or financial-report permission. Order Processing remains availability-only and cannot adjust stock; customers have no admin inventory access.

For local Phase 3N UAT, mandatory staff MFA establishes completed trust only in the current encrypted PostgreSQL session as identity/version and verification time. Enrollment temporarily stores the unconfirmed setup secret **encrypted in the existing Redis cache**, keyed to that server session and user, for at most ten minutes; the session keeps only the pending timestamp. Confirmation deletes the cached value. Redis loss requires enrollment to restart safely. The local session idle lifetime, completed-staff idle and absolute limits, and MFA trust window are configured for 24 hours; a new session, logout, expiry, password reset, role/session revocation or MFA reset requires the normal password-plus-MFA flow again. No remembered-device token or TOTP code is stored in browser storage. Owner-sensitive actions still require separate password-and-TOTP recent authentication within five minutes. Production retains the previous shorter defaults unless its deployment environment explicitly approves and configures a change; see [security policy](../architecture/security.md) and [authentication](identity-authentication.md).

`IdentityPermissionsSeeder` reconciles this grant against existing roles and records before/after permissions in service audit. Run it in the intended environment before role-based UAT; never run `migrate:fresh` against persistent local data. See [inventory operations](inventory.md) and the [Phase 3N UAT report](phase-3n-report.md) for verification status.
